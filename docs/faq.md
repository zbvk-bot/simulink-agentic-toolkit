# Часто задаваемые вопросы

## Окружение

### Как проверить, правильно ли настроен Simulink Agentic Toolkit?

**Из MATLAB:** вызовите `satk_initialize`, затем запустите `validate_installation`:

```matlab
satk_initialize
validate_installation
```

Это последовательно выполняет шесть проверок и выводит сводку:

| № | Проверка | Что проверяется |
|---|-------|-----------------|
| 1 | Версия MATLAB | R2023a или новее |
| 2 | Simulink | Установлен и лицензирован |
| 3 | Точки входа инструментов | Все функции инструментов MCP находятся в пути MATLAB |
| 4 | Разрешение пакетов | Пакеты `+sage` и `+mbd` разрешаются внутри набора инструментов и не перекрыты другими |
| 5 | Бинарный файл MCP-сервера | `matlab-mcp-server` существует в `~/.matlab/agentic-toolkits/bin/` |
| 6 | Связность MCP | `shareMATLABSession` доступен, и коннектор MATLAB запущен |

В выводе используются значки успеха/неудачи/предупреждения, и для каждой неудавшейся проверки предлагается способ исправления. Если все проверки пройдены, итоговый результат — **PASS**, и инструменты MCP готовы к использованию вашим ИИ-агентом для написания кода.

**Из вашего ИИ-агента для написания кода:** убедитесь, что инструменты MCP и навыки (skills) зарегистрированы. Способ проверки зависит от агента:

| Агент | Проверка инструментов MCP | Проверка навыков |
|-------|----------------|--------------|
| Claude Code | `/mcp` | `/skills` |
| GitHub Copilot | Палитра команд VS Code: `MCP: List Servers` | Навыки видны в упоминаниях `@` в чате |
| OpenAI Codex | `codex --list-tools` или проверьте `~/.codex/config.toml` | Проверьте регистрацию в `.codex-plugin/plugin.json` |
| Sourcegraph Amp | Проверьте конфигурацию MCP в `~/.config/amp/settings.json` | Проверьте `amp.skills.path` в настройках |
| Gemini CLI | `gemini --list-tools` или проверьте `~/.gemini/settings.json` | Проверьте регистрацию в `gemini-extension.json` |

Вы должны увидеть MCP-сервер `matlab` с такими инструментами, как `model_overview`, `model_read`, `model_edit`, `model_query_params`, `model_resolve_params` и `model_test`. Для навыков ищите навыки Model-Based Design (например, `building-simulink-models`, `testing-simulink-models`, `simulating-simulink-models`) и навык настройки (`simulink-agentic-toolkit-setup`).

**Типичные способы исправления сбоев:**

- **Не пройдены проверки 1–2 (останавливают выполнение остальных проверок):** обновите MATLAB или установите Simulink.
- **Не пройдены проверки 3–4:** выполните `satk_initialize`, чтобы добавить пути набора инструментов, либо удалите конфликтующие записи путей, которые перекрывают пакеты набора инструментов.
- **Проверка 5 выдаёт предупреждение:** выполните `setupAgenticToolkit("install")`, чтобы загрузить бинарный файл MCP-сервера.
- **Не пройдена проверка 6:** установите MATLAB MCP Server Toolbox (загружается автоматически во время настройки), затем перезапустите MATLAB и повторно выполните `satk_initialize`.
- **`/mcp` не показывает сервер matlab:** повторно запустите навык настройки (`simulink-agentic-toolkit-setup`), чтобы зарегистрировать MCP-сервер у вашего агента, либо проверьте путь к бинарному файлу в конфигурации MCP вашего агента.
- **В `/skills` отсутствуют навыки MBD:** повторно запустите навык настройки, чтобы зарегистрировать навыки глобально, либо убедитесь, что плагин набора инструментов установлен для вашего агента.


## Навык: testing-simulink-models

### Почему для написания тестов используется Gherkin?

Gherkin был выбран в качестве формата написания тестов, поскольку он находится в удачной точке равновесия — LLM генерируют его надёжно, он естественным образом соотносится с тем, как пишутся требования, и люди могут быстро его проверять.

Вместо того чтобы просить LLM напрямую создавать и поддерживать сложные артефакты Simulink Test, агент генерирует простой, легко проверяемый текстовый файл, который `model_test` преобразует в артефакты Simulink Test. Такой подход также работает стабильно во всех версиях MATLAB.

- **Надёжность LLM.** В интернете существует большой корпус текстов на Gherkin, поэтому LLM хорошо обучены на этом синтаксисе и генерируют его очень стабильно. Модель выполнения Gherkin также похожа на pytest — агент выводит ограниченный по структуре файл, запускает его и интерпретирует результаты, — а это ещё один паттерн, на котором LLM обладают обширными данными предобучения.

- **Естественное соответствие требованиям.** Gherkin разработан для тестирования на основе поведения, что напрямую соотносится с тем, как пишутся требования. Нотация EARS (Easy Approach to Requirements Syntax), широко используемая в автомобильной и авиакосмической отраслях, использует ту же логическую структуру — *When \<триггер\>, the system shall \<реакция\>* — просто с другими ключевыми словами. Требование и сценарий на Gherkin — когнитивно один и тот же объект. Это упрощает для агента перевод требований в тестовые файлы и позволяет направить 100% его рассуждений на решение инженерной задачи, а не на управление API инструментов или жизненным циклом тестовых стендов (harness).

- **Проверяемость человеком.** Файл на Gherkin находится на пересечении того, что агенты могут надёжно выводить, и того, что люди могут быстро проверить. По мере масштабирования рабочих процессов с использованием ИИ агенты будут генерировать, а люди — проверять, и эта проверка должна быть когнитивно простой. Gherkin это обеспечивает.

- **Широкая совместимость версий.** Набор инструментов ориентирован на версии MATLAB начиная с R2023a. Gherkin — это простой текстовый формат, который `model_test` преобразует в артефакты Simulink Test, поэтому он работает во всех версиях без зависимости от API, специфичных для конкретной версии.

- **Расширения для конкретной предметной области.** Сама спецификация Gherkin не определяет полный набор семантики, необходимой для тестирования в Simulink (например, входные сигналы, допуски, регистрируемые сигналы). Набор инструментов добавляет дополнительные структурированные разделы для входных данных и проверок, которые агент генерирует вместе со стандартными шагами Given/When/Then.

- **Дальнейшее развитие.** Это не обязательно окончательный ответ. Идеальный интерфейс — такой, который агент может генерировать, а человек — проверять, — будет продолжать развиваться по мере развития как возможностей LLM, так и функций Simulink Test. Разрабатываются бенчмарки MBD GenAI для проведения экспериментов по сравнению компромиссов между различными форматами тестов.
